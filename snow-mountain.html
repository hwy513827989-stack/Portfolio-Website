Overview

How the Ritual Works

The player acts as a shaman trying to calm a snow mountain. Each weather condition requires a different sequence of ritual objects.

The player enters the required sequence, then drags the summoned objects onto the mountain. The program checks the weather, input order, and object placement before triggering sound, particles, and environmental changes.

Weather, Objects, and Program Logic

The program connects weather conditions, ordered inputs, object placement, and visual or audio responses. Each step must be completed in the expected order before the environment changes.

Separate Image Assets

Backgrounds and ritual objects were drawn in Procreate and imported into Java as separate image files. Objects can be shown, hidden, and dragged independently from the background.

Weather Conditions

Each weather state is linked to a specific ritual sequence. The program checks the current condition before accepting the input order and object placement.

Action Responses

Startup instructions explain the controls. During the ritual, sound, particles, object visibility, and environmental changes show whether the player's actions were accepted.

Reflection

Takeaways

LEARNING 01

State Changes Need Clear Confirmation

When environmental changes were too subtle, it was difficult to tell whether an action had been accepted. Sound and particles made successful actions easier to recognise.

LEARNING 02

Drag Targets Need Enough Tolerance

Small or irregular target areas made object placement unreliable. The target zones needed to be larger than the visible illustrated shapes.

IF I DID IT AGAIN — 01

Test Hit Areas Before Final Artwork

I would test clickable, draggable, and target regions before completing the final assets instead of adjusting collision areas after the artwork was finished.

IF I DID IT AGAIN — 02

Add More Types of Input

A future version could use held inputs, traced paths, or timed sequences instead of relying only on clicking and dragging.
